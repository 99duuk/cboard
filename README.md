# Cboard

5개 Codex 계정의 Agent Command Center를 한 터미널 화면에 모아 보는 개인용 도구.

현재 버전: **0.1.0, 로컬 실행 가능**. 2026-10-14 기준.

## 실행

```sh
cboard
```

현재 설치된 실행 명령은 `~/.codex/bin/cboard`다. PATH에 없는 셸에서는 이 경로로 실행한다.

기본 목록은 상태·계정·프로젝트와 관계없이 최근 활동 시각 내림차순이다. 계정·상태 필터와 검색으로 대화를 찾는다. `g`는 전체 최근순 → 프로젝트별 → 계정별 보기로 전환한다. 그룹 보기에서는 각 그룹 안에서 최근순이며, 가장 최근 항목이 있는 그룹부터 표시한다. 최근 대화는 오른쪽에 표시되고, 100열 미만에서는 `d`로 상세, `Esc`로 목록을 본다.

상세 대화는 위에서부터 **마지막 요청 → 마지막 답변** 순서다. 상태 확인은 기본 3초, 전체 목록 갱신은 15초이며, 표시가 같으면 목록을 다시 만들지 않는다. 변경 없는 상태 확인의 캐시 파일 쓰기와 중복 저장 확인 조회도 생략한다. 재개 직전에는 저장 상태를 새로 검사한다.

작업 목록에서 `←/→`는 ‘전체 → 최근 14일 세션이 가장 많은 작업공간 → 다음 작업공간’을 순환한다. 위쪽 작업공간 선택기에서도 직접 고를 수 있다. `bottling-workspace/slot-1`과 `slot-3/frontend`는 bottling-workspace 하나로 합산하며, 선택한 그룹의 각 행에 슬롯 상대 경로를 표시한다. 그룹 안은 최근순이다. 최근 14일은 마지막 활동 시각 기준이며 ‘전체’에서는 오래된 대화까지 기존처럼 표시한다.

현재 작업공간은 목록 위의 청록색 영역에서 이름을 먼저 강조한다. 아래에는 `1/12` 같은 이동 위치·최근 세션 수와 경로를 따로 표시한다. 긴 경로는 한 줄로 줄이고 마우스를 올리면 전체 경로를 확인할 수 있다. 선택기에서도 이름을 먼저 표시한다.

홈에서 직접 시작한 세션은 홈(루트), Desktop/Downloads 아래 세션은 각각 Desktop/Downloads로 묶는다. `~/Documents/workspace/` 바로 아래 프로젝트는 이름과 무관하게 하위 폴더를 같은 그룹으로 합친다. 그 밖의 `*-workspace` 하위도 상위 workspace로 합치며, 일반 Git 저장소는 저장소 루트, 나머지는 작업 폴더로 묶는다. 그룹은 전체 계정의 숨기지 않은 root 세션 수로 집계하며 계정/상태/검색 필터와 독립적이다. 자동 갱신은 기존 그룹 순서를 유지하고 `r`에서 순위를 다시 계산한다. 마지막 선택한 작업공간은 재실행 때 복원한다.

| 키 | 동작 |
| --- | --- |
| ↑ / ↓ | 작업 이동 |
| ← / → | 작업 목록에서 이전/다음 작업공간 (최근 14일 세션 수 순) |
| Enter | 현재 대화를 열거나 재개 명령 복사 |
| F2 | 현재 세션 이름 변경 (입력 후 Enter 저장, Esc 취소) |
| Space | 복구할 항목 선택/해제 |
| R | 저장된 선택 목록을 확인하고 함께 재개 |
| h | 현재 행 숨기기, 숨김 보기에서는 다시 표시 |
| Delete | 현재 대화 영구 삭제 확인창 (Mac에서는 Fn+⌫) |
| H | 숨긴 항목 보기/감추기 |
| / | 검색 |
| g | 전체 최근순/프로젝트별/계정별 보기 전환 |
| r | 새로고침 |
| d / Esc | 상세/목록으로 이동 |
| q | 종료 |

7개 중 5개를 복구하려면 끝낸 2개를 `h`로 숨기고 남은 5개를 `Space`로 선택한다. 다시 실행해도 선택은 남으며 `R`로 재개한다. 현재 행을 숨기는 동작은 다른 선택을 지우지 않는다.

재개 확인창은 첫 번째 사용 가능한 버튼에 포커스한다. `←/↑`, `→/↓`로 ‘터미널에서 열기 / 명령 복사 / 취소’를 이동하고 `Enter`로 선택한 버튼을 실행한다. 비활성 버튼은 건너뛴다. `Tab`과 마우스도 사용할 수 있다.

‘터미널에서 열기’는 항상 새 iTerm2 탭에서 같은 대화를 연다. 이미 열린 탭이 있어도 새 탭을 만들며 대화를 복제하거나 새 thread ID를 만들지는 않는다.

새 탭은 계정 설정의 `iterm_profile`로 생성하고 `iterm_background`가 있으면 해당 배경색을 적용한다. 현재 설정은 기존 셸의 CODEX=Alpha/001e3a, CWORK=Alpha/38220b, CCOMM=Charlie/28152e, CSAY=Bravo/103019, CRIM=Delta/3a1015와 일치한다.

첫 사용자 메시지를 보내지 않은 빈 세션은 서버 메모리에서 Ready로 보이더라도 저장된 대화가 없을 수 있다. 목록에 `미저장`, 상세에 `아직 저장 안 됨`을 표시하고 재개·재개 명령 복사를 막는다. 기존 열린 세션에서 작업을 시작하거나 새 세션을 사용한다. 메시지를 보내 대화가 저장되면 다시 재개할 수 있다.

`F2`는 Codex 원본 세션 이름을 변경한다. 현재 이름이 선택된 입력창에서 새 이름을 입력하고 `Enter`로 저장한다. 계정과 대화 ID는 유지되며 실행 중인 대화도 이름 변경만 수행한다. 빈 이름이나 여러 줄은 허용하지 않는다. Mac에서 F2가 시스템 기능으로 동작하면 `Fn+F2`를 사용한다.

`Delete`는 현재 행 한 개의 원본 대화 삭제 기능이다. 확인창은 ‘취소’에 초기 포커스를 두며 확인어 입력은 없다. 계정·대화·하위 대화 개수를 확인하고 화살표로 ‘영구 삭제’를 선택한 뒤 `Enter`를 누르거나 해당 버튼을 클릭하면 실행된다. `Esc` 또는 ‘취소’는 삭제 없이 닫는다. **대화가 만든 하위 에이전트 대화도 함께 삭제되며 복구할 수 없다.** 프로젝트 파일은 삭제하지 않는다. 단순히 목록에서 감추려면 `h`를 사용한다. 저장된 Ready/Inactive 대화는 삭제를 허용하며, 실제 작업 중·승인 대기·상태 확인 불가 및 임시 하위 대화가 있으면 삭제를 막는다. 이 기능은 iTerm2 탭 생성이나 앱 제어를 사용하지 않는다.

연결 자체를 끝내려면 해당 Codex 터미널에서 `/exit` 후 Enter를 누른다. 마지막 연결이 끝나도 서버의 비활동 유예 때문에 Ready 상태가 최대 30분 남을 수 있다. 저장된 Ready 대화의 삭제는 이 시간을 기다리지 않는다. 첫 메시지 전 빈 세션에는 삭제할 저장 기록이 없을 수 있으므로 목록 정리에는 `h`를 사용할 수 있다.

서버 상태와 삭제 범위를 실행 직전에 다시 확인한다. 다른 클라이언트가 그 직후 다시 연결하는 경쟁 상황까지 원자적으로 막는 기능은 아니다. 삭제 응답이 끊기면 목록을 새로고침하며 자동 재시도하지 않는다. 삭제 후 목록 조회가 실패하면 오래된 metadata가 stale 표시와 함께 남을 수 있다.

## 명령과 설정

```sh
cboard doctor
cboard list --json
cboard list --account cwork --status Ready
cboard detail cwork/THREAD_ID
cboard open cwork/THREAD_ID --copy
```

`open --copy`는 재개 명령을 출력한다. 화면의 ‘명령 복사’는 클립보드에 복사한다. `open`은 iTerm2 탭으로 열며 새 프롬프트를 보내지 않는다.

계정 설정은 `~/.config/cboard/config.toml`이다. 아래 블록을 추가하면 UI 코드 변경 없이 계정을 추가할 수 있다. `id`는 저장된 선택의 식별자이므로 표시 이름만 바꿀 때는 `label`을 바꾼다.

```toml
[[accounts]]
id = "extra"
label = "EXTRA"
codex_home = "~/.codex-extra"
enabled = true
# 선택 사항: iTerm2에 저장된 정확한 프로필 이름과 배경색
iterm_profile = "Alpha"
iterm_background = "001e3a"
```

`iterm_profile`을 생략하면 iTerm2 기본 프로필로 새 탭을 만든다. `iterm_background`는 `#` 없는 6자리 RGB이며 생략하면 프로필 배경을 사용한다. 두 값은 ‘터미널에서 열기’와 `cboard open`에 적용된다. 셸 설정을 변경한 뒤에는 이 파일의 해당 값도 수정한다.

대화와 원본 상태는 기존 Codex 서버에서 읽는다. 설정에 지정된 계정의 daemon이 없으면 마지막 저장 목록과 조회 시각을 표시한다. 숨김과 선택은 `~/.local/share/cboard/state.json`, 본문을 제외한 metadata cache는 `~/.cache/cboard/`에 저장한다.

## 설치·수정·검증

GitHub 저장소에서 설치:

```sh
gh repo clone 99duuk/cboard
cd cboard
sh scripts/install.sh
~/.codex/bin/cboard
```

Python 3.11 이상과 기존 계정별 Codex 서버가 필요하다. 비공개 저장소는 `gh auth login`으로 접근 가능한 계정에서 복제한다.

로컬 소스 검증:

```sh
cd ~/Documents/workspace/cboard
sh scripts/install.sh
.venv/bin/python -m pytest -q
.venv/bin/python scripts/visual_qa.py
.venv/bin/python scripts/benchmark.py --output /tmp/cboard-performance.json
```

독립 가상환경에 `requirements.lock`의 버전을 설치한다. 설치 스크립트는 다른 `cboard` 실행 파일을 덮어쓰지 않는다. 소스를 수정하면 editable 설치에 바로 반영된다.

가상환경·인증 파일·세션 기록·로컬 state 및 실제 작업공간별 집계 원자료는 Git에 포함하지 않는다. 화면 예시는 샘플 데이터로 생성한다.

수정 위치: 계정은 `config.py`, Codex 조회는 `sources/`, 삭제는 `deletion.py`, 이름 변경은 `renaming.py`, 작업공간 경로 규칙은 `workspaces.py`, 필터·통합은 `services.py`, 화면은 `ui/`, 재개 명령과 iTerm2 제어는 `terminals/`. 쓰기 서비스와 터미널은 CLI에서 주입하므로 화면 코드를 바꾸지 않고 다른 연동을 연결할 수 있다.

## 검증과 현재 한계

- 5계정·2,000행 합성 데이터의 변경 없는 반복 갱신 중앙값은 303ms → 22ms였다(5회, 120×35 headless UI). 실제 715행 읽기 표본은 16.6ms → 2.4ms였으며 단일 표본이다. 전체 사용자 체감 속도나 메모리 감소율을 보장하는 수치는 아니다. 상세 조건·원자료는 검증 기록에 있다.
- 실제 5개 계정의 716개 대화를 통합 조회했다. 조회 전후 기존 loaded ID 집합이 같았다.
- CLI 출처 대화와 앱/IDE 출처 대화를 각각 실제 iTerm2에서 재개했다. 현재 정책은 매번 새 탭 생성이며 초기 버전의 탭 재사용 동작은 제거했다.
- 입력·출력 토큰 세부 수치는 현재 `—`로 표시한다.
- 기존 탭을 검색하거나 재사용하지 않는다. 같은 대화를 여러 탭에서 열 수 있으며 각 탭은 같은 원본 thread ID에 연결된다.
- iTerm2 내장 AppleScript 연동을 사용하므로 Python API를 활성화할 필요가 없다. macOS에서 앱 제어가 차단되면 명령 복사를 사용할 수 있다.
- iTerm2 자동화가 한 번 실패하면 남은 탭 열기를 중단하고, 이번 Cboard 실행에서는 ‘터미널에서 열기’를 비활성화한다. 이미 열린 탭과 선택 목록은 유지되며 ‘명령 복사’와 조회는 계속 사용할 수 있다. iTerm2 상태를 확인한 뒤 Cboard를 다시 실행하면 자동 열기를 다시 시도할 수 있다. 별도의 Cboard 실행끼리는 자동화 요청을 직렬화하지만 실패 차단 상태를 공유하지는 않는다.
- daemon을 사용하지 않는 CLI와 원격 세션의 실시간 상태는 검증하지 않았다. 이 계정의 기존 daemon에서 관측한 상태를 표시한다.

## 기준

기존 iTerm2와 계정별 Codex 실행 방식을 사용한다. Codex가 가진 대화와 상태를 조회하고, 사용자가 선택한 대화를 해당 계정으로 재개한다. 작업 완료를 별도로 관리하는 시스템은 만들지 않는다.

변경은 `SPEC.md`의 요구사항 번호와 `PLAN.md`의 검증 항목을 함께 갱신한다. 실제 동작이 달라지면 사전 조사 기록은 당시 관측 사실로 보존하고, 새 검증 결과를 날짜와 함께 추가한다.
